自检题：
1. 422是谁返回的，我有写代码触发它吗：
    是pydantic字段校验返回的，用于这个检查用户输入的字段是否符合要求
2. 500+HTTPException和裸500区别是什么：
    可以自定义返回有用的信息，用于在测试程序中发现程序的问题
3. /healthz为什么是GET而不是POST
    - GET表示读取状态、不改变服务器数据-只读
    - POST表示执行一个动作/提交数据-写入
4. RAG为什么要分块，整篇文档一块塞进去不行吗？
  - 整篇文档过于庞大，全部放进去向量数据库能不能存放是一方面，另一方面是检索检索的是平均语义向量，这样的话当用户查问题的时候可能完全找不到相关的内容
  - 即便能够检索到，我们将全部内容丢给大模型回答的时候，因为文本过多会消耗更多的token
  - 哪怕最后觉得token多消耗无所谓，大模型也有可能因为文本过多出现lost in the middle的问题，就是忽略中间的信息，只看开头和结尾的信息。
5. chunk_size太大/小会出现什么问题
  - 太大：存储成本太大、一次调用消耗的成本大、不方便检索
  - 太小：文本太小，要多次检索汇总才能回答问题、语义信息可能会因为切的块被分割
6. embedding这一步在做什么：
  将文本转化为高维向量，这个向量存储着文本的语义信息。能够用于向量数据库的检索。
7. 如果检索不准怎么办：
  - 数据源问题：文档本身是否包含答案？（很多人忽略这一步）
  - 分块问题：chunk_size 是否合适？语义是否被切断？
  - Embedding 模型问题：是否适合你的语种和领域？中文用英文模型就完蛋
  - 检索 top_k 问题：k 太小可能漏，k 太大可能稀释
  - 检索算法：纯向量 vs 混合检索（向量 + BM25 关键词）
  - Rerank 问题：是否需要加一层 rerank 模型重排
  - Prompt 问题：拼装方式是否让 LLM 能用到检索结果
  - Query 问题：用户 query 太短/太模糊，可以加 query rewriting
